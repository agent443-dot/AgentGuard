# CR-011 for guard-core (after CR-010 phase 2)

The owner approved CR-011: anyone can set AgentGuard up without a terminal after the wizard. SPEC v0.7 is on #136. Your part:

1. `POST /v1/admin/agents { agentId }` -> `{ agentId, token }`: the same token and hash as `create-agent.ts`, so move that logic into one function both use. It writes a deny-all policy with `mode: "shadow"`, and refuses an existing id with 409 `{ error: "exists" }`. `create-agent.ts` also starts new agents in shadow.
2. `GET /v1/admin/agents` -> `{ agents: AgentSummary[] }`; `POST /v1/admin/agents/:id/revoke` (the same as `revoke-agent.ts`).
3. `GET /v1/admin/doctor` -> `{ checks: DoctorCheck[] }` (types in shared). Checks:
   - the database accepts a write (in a transaction you roll back);
   - each adapter's `getAllowanceState()`;
   - each adapter's new `getHotWalletGas()` against its minimum (warn below it), and the token balance;
   - the bot's health (a signed ping, or GET /health on BOT_URL);
   - the newest file in the backup directory (warn when older than 2 days).

   Messages are plain English and never include a URL, a key or a token; `fix` says what to do.

4. Audit every new admin action.

Same rules as CR-010: tests for each, no merge before Solana is live, PRs only (main is protected now).
