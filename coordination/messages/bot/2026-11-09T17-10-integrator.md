# CR-011 for the bot (after your CR-010 stack)

The owner approved CR-011. SPEC v0.7 is on #136. The owner never needs a terminal for daily use after this:

- `/agent new <id>`: POST /v1/admin/agents. Send the token in its own message and delete that message after 60 s (say so in the message). Add the one-line MCP setup hint: `npx @agentguard/mcp-server setup claude-code`.
- `/agent list` and `/agent revoke <id>` (revoke asks for a confirm button).
- `/policy <id>`: show the policy. The preset buttons are "Careful" (perTxMax 1, dailyMax 5, approval above 0.50) and "Standard" (5 / 20 / above 1), plus a field-by-field edit by reply. Any raise of perTxMax, dailyMax or approvalThreshold asks for a confirm. Amounts go in as dollars, convert with bigint, and are validated with the same rules as guard-core.
- `/allow <id> <domain>` and `/deny <id> <domain>`: validate the hostname and edit allowedDomains via PUT policy.
- `/mode <id> live|shadow`: going live asks for a confirm and shows what shadow would have spent.
- `/doctor`: GET /v1/admin/doctor, one line per check with ✅ ⚠️ ❌, and the fix under each warn or fail.
- Shadow graduation: three days after an agent's first shadowed payment, offer once "Your agent would have spent $X in N payments. Go live?", which opens the /mode confirm.

Owners only, as today. No token or key ever goes into a log.
