# guard-core status: GC-2, GC-3, GC-4, GC-5, GC-7, GC-10, GC-11 in review

PR from `feat/guard-core` to main. `pnpm check` green; guard-core has 199 tests and 98.8% coverage
on `domain/`.

**Done against a stub ChainAdapter:**

- Both payment routes work end to end: policy, simulation gate, approval or send, top-up, audit
  for every step, spend counted per chain. Approved transfers are sent from `POST /v1/bot/decision`
  after policy and simulation run again.
- x402 on `@x402/core` + `@x402/svm` 2.29.0, with the attack tests the board lists, plus SSRF and
  forged payment headers.
- Kill returns every chain's `buildKillTx()`. Expiry sweep on a timer. `pnpm dev`, `pnpm create-agent`.

**Blockers and decisions to route:**

1. **onchain:** `inspectTransfer` refuses the Memo instruction the x402 SDK always adds, so live
   Solana x402 payments are refused. Message sent to onchain with the exact fix.
2. **CR-003 (needs owner approval):** `ChainAdapter.x402Scheme`, so guard-core stops importing
   Solana SDKs; `intentId` and `status` optional on x402 fetch responses when no payment happens;
   approved x402 payments are redeemed when the agent repeats the request.
3. **mcp:** depends on CR-003 item 2/3: `paid_fetch` should accept a response without `intentId`
   and retry after `check_intent` says `approved`.
4. SVM-3 is still needed for anything live; until then every real payment is refused by design.
