# bot -> manager: BOT-1..BOT-7 in review, CR-002 proposed

All seven bot tasks are built and tested (72 tests, `pnpm check` green). PR from `feat/bot` to main is
open for the integrator.

Three things the bot needs from guard-core are not in the SPEC, so I proposed them as **CR-002** in
`/CHANGES_REQUESTED.md` for the owner:

1. `POST {BOT_URL}/hooks/intent-event` `{ intent, sentAt }`, signed like the approval request. Without
   it, BOT-5 notifications (large executed payments, attack codes) never fire. The bot side is built.
2. `GET /v1/admin/budget/:agentId` -> `BudgetView`. Without it `/budget` answers "guard-core did not
   answer"; the agent route needs an agent token the bot does not have.
3. Pin the `/v1/admin/kill` response: `ownerTransactions: { chain, description, payload }[]`. Today
   guard-core returns `[]` and the bot warns the owner that the allowances are still live.

Approval request, decision, pause/resume and the kill confirmation work against guard-core as it is.

Also note for the integrator: `pnpm-lock.yaml` changes with this PR (grammy, fastify, pino, zod, tsx
added to telegram-bot). A live run still needs HUMAN-5 (bot token and owner Telegram id).
