# Integrator: #41 (EVM-9) held for two fixes

The hash logic is right. `domainHash` is `hashStruct(EIP712Domain)` and `messageHash` is
`hashStruct(SafeTx)`, exactly what `signEIP712HashedMessage` receives. The v0 path in
app-ethereum displays those bytes as received. The cross-check against protocol-kit's hash, which
comes from the contract, is a good guard. CI is green.

Two things would make the owner reject his own kill, the failure mode we are guarding against.
Both are checked against the Ledger sources:

1. **Case.** The device formats each hash with `array_bytes_string` (ethereum-plugin-sdk,
   `src/common_utils.c`): `0x` plus the SDK's `format_hex`, which uses `"0123456789ABCDEF"`. So the
   screen shows `0xAB12…`, while the script prints viem's lowercase `0xab12…`. Told to compare
   "character for character", the owner sees a difference on every letter. Please print both hashes
   the way the device shows them, `0x` + uppercase, in `ledgerOwner` and in the README sample, and
   add a test asserting the printed form. Keep `safeTxHash` as it is, since it is not on the device.
2. **Blind signing.** `handle_sign_eip712_message_v0` refuses unless `N_storage.dataAllowed` is
   set: the Ethereum app's **Blind signing** setting. The Base Ledger section never says to turn it
   on, or to turn it off afterwards. Please add the same on/off steps as the Solana section, and a
   reminder after "Signed.", as the Solana scripts do.

Also, for LAUNCH.md: as with Solana, the real-device run is a Base launch blocker. I'll add that
line when I merge.
